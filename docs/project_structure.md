# Project Structure

This document describes the overall structure of the project and how the codebase is organized.

The project follows a two-phase design:

1. Prototype Phase – standalone implementation of recommendation models and evaluation
2. Framework Phase – integration of all models into the RecBole framework

---

## 1. High-Level Structure

```
data/
docs/
logs/
notebooks/
results/
src/
```

---

## 2. Folder Descriptions

### data/

Contains all datasets used in the project.

```
data/
├── raw/
├── processed/
└── recbole/
```

* **raw/** → original downloaded datasets
* **processed/** → cleaned and transformed interaction data
* **recbole/** → datasets converted into RecBole format (.inter files)

---

### docs/

Contains all documentation files:

* dataset documentation
* project structure
* additional notes

---

### logs/

Contains the work log and development tracking.

---

### notebooks/

Optional exploratory notebooks for analysis and debugging.

---

### results/

Stores all outputs generated by experiments:

```
results/
├── *_recommendations.csv
├── *_metrics.csv
└── analysis_results/
```

Includes:

* recommendation outputs (prototype phase)
* evaluation metrics
* plots and comparison tables

---

### src/

Contains all source code.

```
src/
├── analysis/
├── datapipeline/
├── evaluation/
├── models/
└── utils/
```

---

## 3. Source Code Modules

### src/analysis/

Used for result comparison and visualization.

Typical tasks:

* aggregate results across models
* generate plots (HR, NDCG, MRR)
* create tables for thesis

---

### src/datapipeline/

Handles all dataset preprocessing.

Responsibilities:

* loading raw datasets
* mapping to unified format (user_id, item_id, timestamp)
* chronological sorting
* train/test splitting
* preparing RecBole .inter files

---

### src/evaluation/ (Prototype Only)

Custom evaluation pipeline used in the initial phase.

Responsibilities:

* computing ranking metrics:

  * HR@K
  * NDCG@K
  * MRR@K
  * Coverage
* evaluating recommendation outputs

**Note:**

This module is part of the prototype phase.
In the final system, evaluation is performed using RecBole.

---

### src/utils/

Shared helper functions.

Responsibilities:

* data loading and saving
* building recommendation lists
* handling user interaction histories
* formatting outputs

---

## 4. Model Structure

```
src/models/
├── base.py
├── popularity/
└── recbole/
```

---

### src/models/base.py

Defines a shared interface for recommender models used in the prototype phase.

---

### src/models/popularity/ (Prototype Phase)

Contains standalone implementations of:

* MostPop
* RecentPop
* DecayPop

Also includes:

* runner scripts (run_*.py)
* evaluation scripts (evaluate_*.py)

**Purpose:**

* initial experimentation
* validation of model logic
* baseline comparisons

---

### src/models/recbole/ (Main System)

Contains all RecBole-related implementations.

```
src/models/recbole/
├── custom_models/
├── prepare_recbole_*.py
├── bpr_wrapper.py
└── run_bpr.py
```

---

#### custom_models/

Core module of the final system.

Contains RecBole-native implementations of:

* MostPop
* RecentPop
* DecayPop

Each model is implemented as a subclass of RecBole base classes (e.g., `GeneralRecommender`).

---

#### Other RecBole Components

* dataset preparation scripts
* BPR integration
* experiment runners

---

## 5. Data Flow

### Phase 1 – Prototype Pipeline

```
raw data
↓
preprocessing
↓
train/test split
↓
custom models
↓
recommendation outputs
↓
custom evaluation
↓
metrics + analysis
```

---

### Phase 2 – RecBole-Based Pipeline

```
raw data
↓
preprocessing
↓
RecBole .inter files
↓
RecBole models:

  built-in (e.g., BPR)
  custom (MostPop, RecentPop, DecayPop)

↓
RecBole training and evaluation
↓
results and logs
```

---

## 6. Design Principles

### Reproducibility

All steps are explicitly defined and can be rerun.

---

### Framework-Based Evaluation

Final experiments are conducted within RecBole to ensure:

* standardized evaluation
* comparability across models
* reproducibility

---

### Modularity

* clear separation between prototype and final system
* reusable components

---

### Extensibility

The structure allows:

* adding new models
* integrating session-based recommendation
* extending to new datasets
